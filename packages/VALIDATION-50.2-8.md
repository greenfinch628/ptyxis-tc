# Fedora 44 — Ptyxis-TC 50.2-8

Installed on Scopuli on October 28, 2026. Upstream version remains 50.2 and the
existing /opt/ptyxis-tab-colors-50.1 prefix and application/settings IDs are retained.
The RPM release revision is incremented to 8. Ubuntu packages and other hosts
were not upgraded in this change.

## Diagnosis and implementation

The checked-in upstream version already uses AdwTabView and AdwTabBar transfers,
but explicitly hides the tab bar with one tab. That removes the drag handle from
a detached tab and the drop target from a one-tab destination. Normal windows
now keep that bar visible. Standalone command-window behavior is unchanged.
A notify::is-transferring-page callback rechecks empty windows once native drag
transfer completes. No custom drag source/target, menu or preference was added.

## Automated verification

- Reproduced the old code's hidden one-tab bar with the focused regression fixture.
- Built application successfully; all four Meson checks passed.
- Real Ptyxis windows and libadwaita page transfers: detach through the application's
  create-window callback, reattach into a one-tab window, move into a multi-tab
  window at a specified position, reorder, and verify closed empty source windows.
- A running shell heartbeat continued across transfers, with the same process
  proxy, VTE PTY, terminal object and retained SESSION_MARKER terminal text.
- Custom Arthur profile identity and label retained; active/inactive manual
  overrides and automatic hostname-derived colors retained.
- Existing right-click clipboard and session-color regression fixtures passed,
  including persisted active/inactive overrides and compatible session restore.
- RPM installed without changing per-user configuration files or the settings and
  profile dconf subtree; checked before/after fingerprints.
- RPM file verification excludes generated ghost cache metadata. The compiled
  schema cache is regenerated by the package script with normal readable mode.
- Installed application terminal-command launch and normal exit smoke-tested
  under an isolated D-Bus session, Xvfb and temporary settings.

The integration test uses native transfer APIs, not physical mouse motion.
Interactive Wayland desktop dragging remains a user verification step because
this agent session has no native desktop control surface. Specifically check
physical detach/reattach, insertion position, and last-tab source-window closure
in the installed application before calling the interactive checklist complete.
